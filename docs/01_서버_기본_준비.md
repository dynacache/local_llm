# 01. 서버 기본 준비

- 작업 날짜: 2026-11-19
- 대상 서버: `192.168.0.193` (Rocky Linux 9), 계정 `root`
- 작업 방법: 노트북에서 SSH 키로 접속해 명령 실행

이 문서는 GPU 드라이버를 설치하기 전에 서버를 "깨끗하고 안전한 상태"로 만드는 단계입니다.
모든 명령은 서버에 접속한 상태에서 실행합니다. 노트북에서 접속하는 방법은 맨 아래 "참고"에 있습니다.

---

## 1. 전체 업데이트와 재부팅

**왜 하나요?** 설치 직후 서버에는 밀린 업데이트가 489개 있었습니다. 그중에는 커널(운영체제의 심장)도 포함됩니다.
NVIDIA 드라이버는 커널 버전에 꼭 맞게 만들어지므로, 드라이버를 깔기 **전에** 커널을 최신으로 올려 두어야 두 번 일하지 않습니다.

```bash
dnf -y update
```
→ 모든 패키지를 최신으로 올립니다. 인터넷이 필요하고 10분 안팎 걸립니다.

```bash
reboot
```
→ 새 커널로 다시 시작합니다. 2~3분간 접속이 끊기는 것이 정상입니다.

**여기까지 잘 됐는지 확인**
```bash
uname -r
```
→ 재부팅 후 커널 버전이 바뀌어 있어야 합니다.

| 항목 | 업데이트 전 | 업데이트 후 |
|---|---|---|
| 커널 | 5.14.0-687.10.1.el9_8 | 5.14.0-741.22.1.el9_9 |
| Rocky 버전 | 9.8 | 9.9 |
| 패키지 | 489개 업데이트 대상 | 478개 내려받아 적용, 약 15분 소요 |

## 2. 서버 이름 바꾸기

**왜 하나요?** 기본 이름 `localhost.localdomain`은 어느 서버인지 알 수 없습니다. 접속 화면과 로그에 이름이 찍히므로 알아보기 쉬운 이름이 좋습니다.

```bash
hostnamectl set-hostname ai-server
```
→ 서버 이름을 `ai-server`로 바꿉니다. 재부팅 없이 바로 적용됩니다.

**확인**
```bash
hostnamectl
```
→ `Static hostname: ai-server`가 보이면 됩니다.

## 3. SSH 접속 규칙: root는 키로만, 일반 사용자는 비밀번호 허용

**왜 하나요?** root(최고 관리자) 계정은 비밀번호 추측 공격의 1순위 표적이라 키(열쇠 파일)로만 들어오게 막습니다.
일반 사용자(`dyadmin`)는 사내망에서만 접속하는 개발용 서버라는 점을 감안해 비밀번호 로그인을 허용했습니다.
일반 사용자로 들어간 뒤 관리자 권한이 필요하면 명령 앞에 `sudo`를 붙입니다. (`dyadmin`은 wheel 그룹에 있어 sudo 사용 가능)

```bash
cat > /etc/ssh/sshd_config.d/00-root-key-only.conf <<'CONF'
# 사내 AI 서버(내부망 전용): 일반 사용자는 비밀번호 로그인 허용, root는 키로만 접속
PasswordAuthentication yes
PermitRootLogin prohibit-password
CONF
```
→ SSH 설정에 규칙 파일을 추가합니다. 원래 설정 파일은 건드리지 않습니다.
파일 이름이 `00-`으로 시작하는 이유: 설치 때 자동으로 생긴 `01-permitrootlogin.conf`(root 비밀번호 로그인 허용)보다 먼저 읽히게 하기 위해서입니다.
SSH는 같은 항목이 여러 번 나오면 **먼저 나온 것**을 따릅니다.

```bash
sshd -t && systemctl reload sshd
```
→ 설정 문법을 검사하고(`-t`) 문제가 없으면 SSH 서비스에 다시 읽게 합니다. 기존 접속은 끊기지 않습니다.

**확인**
```bash
sshd -T | grep -E "^(permitrootlogin|passwordauthentication) "
```
→ `permitrootlogin without-password`, `passwordauthentication yes` 두 줄이 나와야 합니다.

**노트북에서 접속하는 방법**
```powershell
ssh dyadmin@192.168.0.193     # 일반 사용자, 비밀번호 입력
ssh root@192.168.0.193        # 키가 등록된 노트북에서만 가능, 비밀번호 불가
```

## 4. 7.3TB 디스크 포맷과 `/data` 연결

**왜 하나요?** 운영체제가 든 NVMe(232GB)에 수십 GB짜리 모델 파일을 쌓으면 금방 찹니다.
비어 있는 HDD 7.3TB를 `/data`라는 이름으로 붙여서 모델, 수집 문서, 검색 색인을 여기에 둡니다.
**주의:** 포맷하면 그 디스크의 내용은 모두 지워집니다. 조사(00 문서)에서 이 디스크는 비어 있음을 확인했습니다.

```bash
lsblk /dev/sda
```
→ 포맷 대상이 7.3T짜리 `sda`이고 아래에 파티션이 없는지 눈으로 다시 확인합니다.

```bash
parted -s /dev/sda mklabel gpt mkpart data xfs 1MiB 100%
```
→ 디스크에 GPT 방식의 칸 나누기 표를 만들고, 전체를 하나의 칸(파티션 `sda1`)으로 잡습니다.

```bash
mkfs.xfs -L data /dev/sda1
```
→ 그 칸을 XFS 형식으로 포맷합니다. XFS는 Rocky Linux 기본 형식이고 큰 파일에 강합니다.

```bash
mkdir -p /data
echo "LABEL=data  /data  xfs  defaults,nofail  0 0" >> /etc/fstab
systemctl daemon-reload
mount /data
```
→ `/data` 폴더를 만들고, 부팅 때마다 자동으로 붙도록 등록(`fstab`)한 뒤 지금 바로 붙입니다.
`nofail`은 혹시 디스크가 빠져 있어도 서버 부팅이 멈추지 않게 하는 안전장치입니다.

```bash
mkdir -p /data/models /data/docs /data/index
```
→ 모델 파일, 수집 문서, 검색 색인을 둘 폴더 세 개를 만듭니다.

**확인**
```bash
df -h /data
```
→ 크기 7.3T, 마운트 위치 `/data`가 보이면 됩니다.

## 5. 빌드 도구 설치

**왜 하나요?** llama.cpp는 소스 코드를 받아 서버에서 직접 "조립(빌드)"합니다. 조립 도구인 cmake가 필요하고,
NVIDIA 드라이버가 커널 업데이트 때 자동으로 다시 만들어지게 하는 dkms도 미리 넣습니다.

```bash
dnf -y install epel-release
```
→ 추가 프로그램 창고(EPEL)를 등록합니다. dkms는 여기에 있습니다.

```bash
dnf -y install cmake dkms python3-pip git gcc gcc-c++ make
```
→ 조립 도구와 파이썬 패키지 도구를 설치합니다. 이미 있는 것은 건너뜁니다.

**확인**
```bash
cmake --version && dkms --version && pip3 --version
```
→ 세 줄 모두 버전이 찍히면 됩니다.

| 도구 | 설치된 버전 (2026-11-19) |
|---|---|
| cmake | 3.31.8 |
| dkms | 3.4.4 |
| pip3 | 21.3.1 (python 3.9) |
| EPEL | 등록됨 |

> 일반 사용자(`dyadmin`)로 접속했다면 `dnf` 앞에 `sudo`를 붙입니다.

## 참고: 노트북에서 서버에 접속하는 방법

1. 일반 사용자: PowerShell에서 `ssh dyadmin@192.168.0.193` 후 비밀번호 입력. 관리자 명령은 앞에 `sudo`.
2. root(키 등록된 노트북만): 처음 한 번 `ssh-keygen -t ed25519`로 열쇠를 만들고, 공개키(`.pub`)를 서버의 `/root/.ssh/authorized_keys`에 붙여 둔 뒤 `ssh root@192.168.0.193`.
3. 접속이 끊겼다 다시 될 때(재부팅 등)는 1~3분 기다린 뒤 다시 시도합니다.
