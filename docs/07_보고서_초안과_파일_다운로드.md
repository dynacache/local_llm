## A. 주간·월간 보고서 초안 (AI가 숫자를 문장으로)

### A-1. 왜

보고서 숫자(건수, 담당자별 통계, 지연 목록, 계약 만료 예정)는 이미 `weekly_reports`, `monthly_reports`에 자동 저장된다.
남은 일은 팀장이 그 숫자를 문장으로 옮겨 적는 것. 이 부분만 AI가 **초안**으로 대신하고, 사람이 고쳐서 **확정**한다.
AI는 계산을 하지 않는다. 숫자는 전부 PHP가 계산해 넘기고, AI는 문장만 만든다.

### A-2. 동작 흐름

```
① 보고서 생성 (기존: 월요일 06:00 스케줄러 또는 "지금 생성" 버튼)
② (추가) 생성 직후 report_narrative_core.php 가
     보고서 숫자 + 지난 기간 숫자 + PHP가 계산한 증감·비율 + 글 형식 지침  →  AI 서버 (8080, 비스트리밍)
③ 20~60초 후 한국어 초안 수신 → 숫자 대조 검사 → weekly_reports.ai_summary 에 저장
④ "보고서" 탭 상단에 [AI 초안] 상자 표시: [다시 생성] [복사] [확정]
⑤ 팀장이 고쳐서 [확정] → note 칸에 저장, "확정됨 · 누가 · 언제" 표시
```

AI 서버가 꺼져 있거나 실패하면 ②③만 건너뛰고 보고서 자체는 기존대로 저장된다 (초안 상자에 "AI 서버에 연결하지 못해 초안을 만들지 못했습니다. [다시 생성]" 표시).

### A-3. 데이터베이스 변경 (작업자가 phpMyAdmin 또는 SQL로 실행)

```sql
ALTER TABLE weekly_reports
  ADD COLUMN ai_summary TEXT NULL,
  ADD COLUMN ai_generated_at DATETIME NULL,
  ADD COLUMN ai_model VARCHAR(100) NULL,
  ADD COLUMN ai_check VARCHAR(200) NULL,
  ADD COLUMN note TEXT NULL,
  ADD COLUMN note_updated_by VARCHAR(100) NULL,
  ADD COLUMN note_updated_at DATETIME NULL;

ALTER TABLE monthly_reports
  ADD COLUMN ai_summary TEXT NULL,
  ADD COLUMN ai_generated_at DATETIME NULL,
  ADD COLUMN ai_model VARCHAR(100) NULL,
  ADD COLUMN ai_check VARCHAR(200) NULL;
```
- 월간은 `note`, `note_updated_by`, `note_updated_at`이 이미 있으므로 추가하지 않는다.
- `ai_check`: 숫자 대조 결과. 비어 있으면 이상 없음, 값이 있으면 "검토 필요" 띠를 띄운다.
- 기존 행과 데이터는 바뀌지 않는다. 실행 전 DB 백업 한 번.

### A-5. AI에게 넘기는 자료 (PHP가 만드는 JSON)

AI가 계산할 일이 없도록 **증감과 비율은 PHP가 계산해서 넣는다.** 주간 예시:

```json
{
  "기간": "2026-11-10(월) ~ 2026-11-16(일)",
  "건수": {"전체": 14, "유지보수점검": 8, "기술지원": 5, "사업": 1},
  "지난주_건수": {"전체": 11, "유지보수점검": 6, "기술지원": 4, "사업": 1},
  "지난주_대비": {"전체": "+3", "유지보수점검": "+2", "기술지원": "+1", "사업": "0"},
  "월점검": {"대상": 50, "완료": 26, "진행률": "52%"},
  "담당자별": [{"이름": "한지원", "전체": 6, "점검": 4, "기술지원": 2, "사업": 0}, ...],
  "점검주기별": [{"주기": "월간", "대상": 40, "완료": 20}, {"주기": "분기", "대상": 10, "완료": 6}],
  "지연": [{"고객사": "강진군청", "업무": "서버 팬 교체", "담당": "한지원", "예정일": "11-19", "지연일수": 3}],
  "미처리_기술지원": [{"고객사": "나주시청", "업무": "...", "담당": "...", "예정일": "11-24"}, ...],
  "현장별_완료": [{"현장": "영광군청", "건수": 3, "담당": "..."}, ...]
}
```
- 기존 `weekly_reports`의 `engineer_stats`, `delayed_items`, `maint_cycle_stats`, `maint_site_completions`, `tech_pending_items`(JSON 칸)를 그대로 한글 키로 바꿔 담는다. 새 조회는 "지난주 행 하나" 뿐.
- 월간은 `monthly_reports.data`(JSON)에서 같은 방식으로: 고객사별, 주차별 추이, 분류별 접수·완료, 파트 구매 단계, 점검 미완료 목록, 사업 진행, 다음 달 점검 예고, 계약 만료 예정, 지난달 수치와 증감.
- 목록은 각 최대 15개. 넘으면 "외 N건"을 PHP가 붙인다.

### A-6. AI 지침 (system 메시지 전문)

```
당신은 알앤비시스템(주) 기술지원팀의 보고서 작성 담당입니다.
아래 JSON 자료만 근거로 한국어 보고서 초안을 작성합니다.

규칙:
1. 자료에 있는 숫자, 이름, 고객사, 날짜만 씁니다. 자료에 없는 사실은 절대 쓰지 않습니다.
2. 계산하지 않습니다. 증감과 비율은 자료에 적힌 값을 그대로 옮깁니다.
3. 목록이 비어 있으면 그 항목에 "없음"이라고 씁니다.
4. 평가나 추측("순조롭다", "문제없어 보인다")은 쓰지 않습니다. 사실만 씁니다. 단, 지연 건과 미완료 건은 "우선 처리 필요"로 표시합니다.
5. 존댓말, 보고서 문체. 전체 700~1,000자(주간) / 1,200~1,800자(월간).
6. 아래 형식과 제목을 그대로 지킵니다. 제목을 바꾸거나 항목을 더하지 않습니다.

형식(주간):
[기술지원부 주간 보고 {기간}]

■ 요약
(3문장: 전체 건수와 지난주 대비, 월 점검 진행률, 지연·주의 사항)

■ 처리 현황
담당자별: (이름 건수, 쉼표로)
점검 주기별: (주기 완료/대상)
현장별 완료: (현장 건수, 최대 5개, 나머지는 "외 N곳")

■ 주의가 필요한 건
(지연 목록을 "- 고객사 / 업무 / 담당 / 예정일 (N일 지연)" 한 줄씩. 없으면 "없음")

■ 다음 주 예정
(미처리 기술지원을 "- 고객사 / 업무 / 담당 / 예정일" 한 줄씩, 최대 8개, 나머지는 "외 N건". 없으면 "없음")

■ 특이사항
(자료만으로 알 수 없으면 "없음")
```
월간 형식은 제목을 `[기술지원부 월간 보고 {YYYY년 M월}]`로 하고, "■ 처리 현황"에 고객사별·분류별·파트 구매 단계를, "■ 다음 달 예정"에 점검 예고와 **계약 만료 예정**을 넣는다. 나머지 규칙은 같다.

호출 옵션: `temperature 0.2`, `max_tokens 1500`(주간) / `2500`(월간), `enable_thinking false`.

### A-7. 숫자 대조 검사 (지어내기 방지)

`report_narrative_core.php`가 초안을 받은 뒤:
1. 자료 JSON에 나오는 모든 숫자(건수, 비율의 숫자 부분, 날짜의 월·일, 지연일수)를 집합으로 만든다.
2. 초안에서 숫자를 전부 뽑아 그 집합에 없는 것을 찾는다.
3. 없는 숫자가 있으면 `ai_check = "자료에 없는 숫자: 17, 23"`으로 저장하고, 화면에 "검토 필요" 띠를 띄운다. 초안은 그대로 보여 준다(사람이 판단).
4. 자료에 있는 고객사 이름이 아닌 고유명사가 있는지는 검사하지 않는다(과하게 걸림). 대신 규칙 1을 지침에 둔다.

> **설계자 확인 필요 (설계와 다르게 한 곳)**
> 1. **확정본 저장 칸**: 설계는 `note`에 저장하지만, 월간 `note`는 팀장이 직접 쓰는 "특이사항 및 건의" 칸이라 덮어쓰면 기존 내용이 사라짐. 두 표 모두에 `ai_final`, `ai_final_by`, `ai_final_at` 전용 칸을 두고 특이사항은 그대로 둠. 주간에 `note` 칸은 추가하지 않음.
> 2. **DB 칸 추가 방식**: 코드가 `SHOW COLUMNS`로 확인한 뒤 없으면 `ALTER TABLE`을 시도하되, 권한이 없으면 false를 돌려주고 화면에 "준비 안 됨"을 띄움. 실제 칸 추가는 관리자가 SQL로 한 번 실행(A-11).
> 3. **주간 "주의가 필요한 건" 줄 형식**: 저장된 지연 목록(`delayed_items`)에 예정일이 없어 `- 고객사 / 업무 / 담당 (N일 지연)`으로 씀.

## B. 파일 내려받기 (AI → 직원)

### B-1. 왜

매니저 창은 글만 주고받는다. "미완료 점검 목록 엑셀로 줘", "이 명령 스크립트로 만들어 줘", "주간 보고서 워드로 줘"에 답하려면
**AI가 내용을 정하고 PHP가 파일로 포장해 내려주는** 길이 필요하다. 원칙 세 가지:
1. **AI는 내용만, 파일 형식은 PHP가.** AI가 엑셀 바이트를 만들지 않는다. 검증된 라이브러리가 만든다.
2. **표 데이터는 DB 조회 결과를 PHP가 직접 넣는다.** AI가 표를 손으로 옮겨 적으면 행이 빠지거나 바뀐다.
3. **스크립트는 저장만, 실행은 절대 안 함.** 직원이 읽고 자기 판단으로 실행한다.

### B-2. 동작 흐름

```
직원: "이번 달 미완료 점검 목록을 엑셀로 줘"
 → AI: get_monthly_maintenance(status=pending) 호출  (기존 도구)
 → AI: make_table_file(format="xlsx", title="11월 미완료 점검", from_tool_result=true) 호출  (새 도구)
 → PHP: 직전 도구 결과(행 배열)를 PhpSpreadsheet로 .xlsx 생성 → files/chat/ 에 저장 → 브라우저에 file 이벤트
 → 대화창: 📎 11월_미완료_점검.xlsx (24행, 18KB) [내려받기]
 → AI: "미완료 24건을 엑셀로 정리했습니다. 담당자별로 보면…" (평소처럼 글 답변)
```

### B-3. 새 도구 3개 (`api/chat_tools.php`의 `chatToolCatalog()`에 추가)

| 도구 | 매개변수 | 하는 일 | 권한 |
|---|---|---|---|
| `make_text_file` | `filename`(확장자 포함: txt, md, csv, sql, sh, ps1, py, bat), `content` | 내용을 그대로 파일로 저장 | 없음(누구나) |
| `make_table_file` | `format`(xlsx 또는 csv), `title`, `from_tool_result`(true면 직전 조회 결과 사용), `columns`(선택, 열 순서·제목), `rows`(from_tool_result가 false일 때 AI가 직접 준 행) | 표 → xlsx(제목 굵게, 열 너비 자동, 날짜 형식) 또는 csv(UTF-8 BOM, 엑셀에서 한글 정상) | 직전 조회 도구의 권한을 따름 |
| `make_docx_file` | `title`, `sections`([{"heading": "...", "paragraphs": [...], "table": {columns, rows}}]) | PHPWord로 워드 문서. 보고서 초안(A)을 "워드로 줘"에 연결 | 없음 |

- `from_tool_result=true`를 위해 `chat_stream.php`가 **직전 도구의 원본 결과(잘리기 전)** 를 변수에 보관한다. AI에게는 지금처럼 잘린 결과를 보여 주되, 파일에는 전체(최대 5,000행)를 넣는다.
- 도구 결과로 AI에게 돌려주는 것: `{"file": "11월_미완료_점검.xlsx", "rows": 24, "size": "18KB", "url": "api/chat_file_download.php?t=..."}`. AI는 이 정보를 글로 안내만 한다.
- 도구 설명(`description`)에 예시 질문을 넣는다: "엑셀로 줘", "파일로 만들어 줘", "스크립트 작성해 줘", "워드로 정리해 줘".

### B-4. 파일 저장과 내려받기

| 항목 | 설계 |
|---|---|
| 저장 위치 | `dashboard/files/chat/` (NAS). `.gitignore`에 `files/` 추가 |
| 파일명 | `{YYYYMMDD}_{사용자id}_{무작위 24자}_{원래이름}` . 무작위 토큰이 주소 역할 |
| 내려받기 | `api/chat_file_download.php?t={토큰}` : 로그인 확인 → 토큰으로 파일 찾기 → **만든 사람 본인만** 허용 → `Content-Disposition: attachment` |


> - (나) 다른 직원 계정으로의 거부를 코드가 아니라 눈으로 확인할 것. 시험용 일반 계정을 하나 만들어 내려받기 주소와 첨부 도구가 거부되는지 시험하고 기록.

## C. 파일 올리기와 로그 분석 (직원 → AI)

### C-1. 왜

매니저 창은 글만 받는다. "이 로그 좀 봐 줘", "이 계약서 요약해 줘", "이 엑셀에서 만료 계약만 골라 줘"에 답하려면 직원이 파일을 올리고 AI가 그 내용을 읽어야 한다.
기술지원부에서는 특히 **고객사 서버 로그 분석**이 바로 쓸모 있다: `/var/log/messages`, `dmesg`, Synology·QNAP 로그 내보내기, iDRAC·iLO 이벤트 로그(SEL), 스위치 로그, 백업 작업 로그.

원칙 세 가지:
1. **PHP가 텍스트로 바꾸고, AI는 텍스트만 본다.** 파일 자체를 AI 서버로 보내지 않는다.
2. **로그는 통째로 넣지 않는다.** AI가 한 번에 읽는 상한(32K 토큰 ≈ 로그 1,000~1,500줄)보다 대부분 크므로, PHP가 먼저 줄이고 AI가 도구로 더 좁혀 가며 본다.
3. **AI의 로그 해석은 추정이다.** 근거가 된 로그 줄을 함께 보여 주고, 판단은 직원이 한다.

### C-2. 동작 흐름

```
① 직원: 클립 버튼으로 messages.log 첨부(또는 창에 끌어다 놓기) + "어제 저녁 재부팅 원인 봐 줘"
② 브라우저 → api/chat_upload.php : 파일 저장(B의 chat_files 표·files/chat/ 재사용, 본인 전용, 7일)
   → 종류별 텍스트 추출 → 줄이기(C-4) → "첨부 요약본" 생성 → 첨부 id와 요약 통계(줄 수, 기간, 중요 줄 수) 반환
③ chat.js: 말풍선에 첨부 카드 표시(📎 이름, 12,480줄 → 중요 줄 312줄, 2026-11-19 00:00~23:59)
④ 질문 전송 시 messages에 첨부 id를 함께 보냄
⑤ chat_stream.php: 시스템 지침에 "첨부 파일 요약본"을 붙이고, 첨부 전용 도구(C-5)를 tools에 추가해 AI 서버 호출
⑥ AI: 요약본을 읽고 답하거나, 도구로 특정 구간·단어를 더 조회한 뒤 답함. 근거 줄을 인용
```

### C-3. 받는 파일 종류와 추출 방법

| 종류 | 확장자 | 추출 | 비고 |
|---|---|---|---|
| 텍스트·로그 | txt, log, csv, conf, json, xml, out | 그대로 (인코딩 감지: UTF-8, EUC-KR, UTF-16) | 로그는 C-4 줄이기 적용 |
| PDF (텍스트형) | pdf | `smalot/pdfparser` (Composer) 또는 NAS의 `pdftotext` | 스캔본(글자 추출 0)은 "스캔 문서는 아직 지원하지 않음" 안내. 비전 모델(docs/06 GPU 3) 이후 |
| 워드 | docx | PHPWord (B에서 설치) | 표는 탭 구분 텍스트로 |
| 엑셀 | xlsx, xls, csv | PhpSpreadsheet (B에서 설치) | 시트별로 "시트명" + 행. 최대 2,000행 |
| 압축 | zip, tar.gz, tgz | 풀어서 안의 허용 종류만 추출 (최대 20개 파일) | 고객사 로그 묶음 대응. 경로 탈출(`../`) 차단 |
| 이미지 | png, jpg | **이번 범위 밖** | 비전 모델 이후 |
| 한글 | hwp, hwpx | hwpx는 ZIP 안의 XML에서 텍스트 추출 가능, hwp는 미지원 | hwpx만 시도 |

허용하지 않는 종류는 올리기 단계에서 거부한다. 실행 파일(exe, sh, ps1, bat)은 **분석 대상으로도 받지 않는다** (텍스트로 올리면 읽기만 함).

### C-4. 로그 줄이기 규칙 (PHP, 업로드 직후 한 번)

로그로 판단하는 기준: 확장자가 log/out이거나, 줄의 70% 이상이 날짜·시각으로 시작하는 txt.

| 순서 | 규칙 | 수치 |
|---|---|---|
| 1 | 전체 통계 | 총 줄 수, 첫·끝 시각, 파일 크기. 요약본 머리에 넣음 |
| 2 | 중요 줄 추리기 | 다음 단어가 든 줄과 앞뒤 2줄: `error, fail, failed, warn, warning, crit, critical, panic, oops, segfault, timeout, timed out, degraded, offline, reboot, shutdown, kernel:, I/O error, SMART, raid, md:, link down, not responding, denied, refused`. 대소문자 무시 |
| 3 | 반복 묶기 | 시각 부분을 뺀 메시지가 같은 줄이 3번 이상 연속·근접(1분 안)하면 `[×N 반복, 첫 시각~끝 시각] 메시지` 한 줄로 |
| 4 | 상한 | 요약본은 중요 줄 기준 최대 400줄, 8,000토큰 안. 넘으면 시간순으로 고르게 솎아 내고 "총 N줄 중 400줄 표시, 도구로 구간 조회 가능" 표시 |
| 5 | 원본 보관 | 줄이기 전 전체 텍스트는 `files/chat/` 에 `.txt`로 두어 C-5 도구가 읽음 |

줄이기 결과가 비어 있으면(중요 단어가 하나도 없으면) 처음 100줄 + 마지막 100줄을 요약본으로 쓴다.

### C-5. 첨부 전용 도구 2개 (`api/chat_tools.php`에 추가, 첨부가 있는 대화에서만 tools에 포함)

| 도구 | 매개변수 | 하는 일 | 결과 상한 |
|---|---|---|---|
| `search_attachment` | `attachment_id`, `keyword`(정규식 아님, 부분 일치, 여러 개면 공백 구분 AND), `context_lines`(앞뒤 줄, 기본 2), `max_hits`(기본 50) | 원본 텍스트에서 단어가 든 줄과 앞뒤 줄 반환 | 50건, 6,000자 |
| `read_attachment_range` | `attachment_id`, `from_line`, `to_line` 또는 `from_time`, `to_time`(로그) | 지정 구간의 원문 반환 | 300줄, 8,000자 |

- 첨부 id는 로그인한 사용자의 것만 유효 (B의 `chat_files.user_id` 대조).
- 도구 설명(`description`)에 예시: "로그에서 raid 관련 줄만 찾기", "20:00~20:30 구간 원문 보기".
- 한 질문에 도구 호출 상한은 기존 `CHAT_MAX_TOOL_ROUNDS`(3)를 **첨부가 있을 때 5로** 올린다. 로그 분석은 좁혀 가는 횟수가 더 필요하다.

### C-6. 시스템 지침 추가분 (첨부가 있을 때 `$systemPrompt`에 덧붙임)

```
직원이 파일을 첨부했습니다. 아래 "첨부 파일 요약본"은 PHP가 중요 줄만 추린 것입니다.
- 요약본만으로 부족하면 search_attachment, read_attachment_range 도구로 원문을 더 조회하세요.
- 로그 분석 답변은 반드시 (1) 결론 추정, (2) 근거가 된 로그 줄 인용(시각 포함), (3) 확인 권장 사항 순으로 씁니다.
- 로그에 없는 원인을 단정하지 않습니다. 가능성이 여러 개면 가능성 순으로 나열합니다.
- 첨부 내용 중 비밀번호, 토큰, 키로 보이는 문자열은 답변에 옮겨 적지 않습니다.
```

### C-7. 파일과 변경 범위

| 파일 | 변경 | 역할 |
|---|---|---|
| `api/chat_upload.php` | **새 파일** | 로그인·CSRF 검사 → 종류·크기 검사 → 저장(B 구조) → 추출 → 줄이기 → `chat_files`에 `extracted_name`, `summary`, `line_count`, `time_range` 기록 → JSON 반환 |
| `chat_extract.php` | **새 파일** | 종류별 텍스트 추출 함수, 인코딩 감지, 압축 해제, 로그 줄이기(C-4). CLI 시험용 진입점 포함 |

| `api/chat_stream.php` | 첨부 처리 | messages의 첨부 id 검증 → 요약본을 지침에 삽입 → 도구 라운드 상한 5 |
| `chat.js` | 클립 버튼, 끌어다 놓기, 첨부 카드, 전송 시 첨부 id 동봉 | 첨부 카드는 대화 보관에 포함. 업로드 중 진행 표시 |
| `chat_files` 표 | 칸 추가 | `kind`(download/upload), `extracted_name`, `summary` TEXT, `line_count`, `time_range` |
| `chat_file_cleanup.php` | 기존 | 올린 파일과 추출본도 7일 후 삭제 (B와 같은 스크립트) |

```sql
ALTER TABLE chat_files
  ADD COLUMN kind VARCHAR(10) NOT NULL DEFAULT 'download',
  ADD COLUMN extracted_name VARCHAR(300) NULL,
  ADD COLUMN summary MEDIUMTEXT NULL,
  ADD COLUMN line_count INT NULL,
  ADD COLUMN time_range VARCHAR(60) NULL;
```
(A절과 같은 이유로 `rnb_app` 계정에 ALTER 권한이 없으면 관리자가 실행)

> **설계자 확인 필요 (설계와 다르게 한 곳)**
> 1. **`chat_files` 표 대신 .json 곁파일** (B절과 같은 이유, `rnb_app`에 CREATE·ALTER 권한 없음). 원본 파일은 보관하지 않고 추출된 글(`_extracted.txt`)만 7일 보관.
> 2. **압축·워드·엑셀·hwpx 풀기**: NAS PHP에 zip·zlib 확장이 없어 NAS의 `7z`·`tar`·`gzip`을 셸로 부름. 모두 표준 출력(stdout)으로만 풀어 디스크에 풀어 놓지 않으므로 경로 탈출이 생기지 않음. 인자는 모두 `escapeshellarg`, 7z는 와일드카드 끔(`-spd`), tar는 `--no-wildcards`. PDF는 NAS의 `pdftotext`.
> 3. **중요 단어 3단계**: 사건(부팅·정상 종료·패닉·oom·Machine check·lockup) > 강한 단어 > 약한 단어(`warn`, `kernel:`). 설계의 목록에 한국어 단어(오류·에러·실패·장애·응답 없음·경고·주의)를 더함. `kernel:`은 커널 줄 전체에 붙어 강한 단어로 두면 요약본이 커널 줄로만 차서 약한 단어로 내림.
> 4. **부팅 목록 표**: 로그에서 부팅(`kernel: Command line:`)을 찾아 요약본 맨 위에 "부팅 시각 / 직전 마지막 기록의 줄 번호·시각·간격 / 정상 종료 기록 유무"를 PHP가 계산해 넣음. 32B 모델이 요약본 사이에서 직전 줄을 스스로 찾지 못해 추가.
> 5. **올리기 상한**: 설계는 원본 50MB지만 NAS PHP 업로드 한도가 32MB(`upload_max_filesize`, `post_max_size`)라 실제 상한은 32MB. 넘으면 "NAS 업로드 한도(32M)를 넘습니다" 안내. 늘리려면 Web Station PHP 프로필에서 60M 이상.
> 6. **지침에 넣는 요약본 합계 2만 자**: 첨부가 여럿이면 나눠서 넣고, 잘린 부분은 도구로 조회하라고 안내.

> **설계자 검토 결과 (2026-11-20, C절)**
> 1~6 모두 승인.
> - 1(곁파일, 원본 미보관): 추출본만 7일 두는 것은 개인정보 면에서 설계보다 나음.
> - 2(셸 도구로 압축 해제): 경로 탈출 차단과 `escapeshellarg`는 적절. **보완 요청 (다)**: 모든 셸 호출에 실행 시간 상한(`timeout 30`)과 표준 출력 바이트 상한(합계 100MB, 넘으면 중단하고 "압축 해제 결과가 너무 큽니다" 안내)을 걸 것. 작은 zip이 수 GB로 풀리는 파일(zip bomb)과 멈춤을 막기 위함. 압축 안의 압축은 풀지 않음을 명시.
> - 3(중요 단어 3단계, 한국어 단어 추가)·4(부팅 목록 표): 실제 로그로 시험하며 나온 개선으로 설계보다 실용적. 특히 "32B가 요약본에서 직전 줄을 스스로 찾지 못해 PHP가 계산"은 좋은 판단. 설계의 C-4는 이 구현을 기준으로 읽는다.
> - 5(32MB 한도): 사용자가 PHP 한도를 올렸으므로 다음 실행 때 실제 한도를 확인해 안내 문구의 숫자를 맞출 것.
> - 6(요약본 2만 자): 타당.
