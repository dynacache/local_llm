# 00. 서버 현황 (설치 시작 전 조사 기록)

- 조사 날짜: 2026-11-19
- 조사 방법: 회사 노트북에서 SSH로 접속해 읽기 전용 명령만 실행 (서버 설정은 바꾸지 않음)
- 접속 정보: `192.168.0.193`, 계정 `root`, 노트북의 SSH 키로 접속 (비밀번호 없이)

이 문서는 "설치를 시작하기 전에 서버가 어떤 상태였는지"를 남기는 기록입니다.
나중에 문제가 생겼을 때 "원래는 어땠지?"를 확인하는 용도로 씁니다.

## 1. 하드웨어

| 항목 | 확인 결과 | 비고 |
|---|---|---|
| 기종 | GIGABYTE G242-Z10 (메인보드 MZ12-HD1) | GPU를 4장까지 꽂을 수 있는 2U 서버. 3장째 GPU 추가 가능 |
| CPU | AMD EPYC 7702, 64코어 | 하이퍼스레딩(SMT)이 꺼져 있어 64스레드로 보임. BIOS에서 켜면 128스레드 |
| 메모리 | 125GB, 스왑 16GB | 여유 충분 |
| GPU | NVIDIA GeForce RTX 3090 24GB × 2장 | PCI 주소 01:00.0, 81:00.0 |
| 시스템 디스크 | NVMe 232GB (WD Blue SN570) | 운영체제 설치됨, 사용 5.4GB |
| 추가 디스크 | HDD 7.3TB (Seagate ST8000NM000A) | **비어 있음(포맷 안 됨)**. 모델 파일·문서 보관용으로 쓸 예정 |
| 네트워크 | 포트 4개 중 eno1 하나만 연결 | 192.168.0.193/24 |

> 용어: **SMT(하이퍼스레딩)**는 코어 하나를 두 개처럼 쓰는 기능입니다. GPU로 AI를 돌릴 때는 영향이 작습니다.

## 4. GPU 드라이버 상태

- **NVIDIA 드라이버 없음** (`nvidia-smi` 명령이 없음)
- 리눅스 기본 오픈소스 드라이버 **nouveau**가 올라가 있음 → NVIDIA 드라이버 설치 전에 이것을 막아야 함
- **보안 부팅(Secure Boot) 꺼짐** → 드라이버 서명 절차가 필요 없어 설치가 단순함

> 용어: **nouveau**는 리눅스가 기본으로 쓰는 NVIDIA 호환 드라이버입니다. 화면은 나오지만 AI 계산에는 못 씁니다.

## 5. 보안 설정

| 항목 | 확인 결과 | 판단 |
|---|---|---|
| 방화벽(firewalld) | 켜짐. ssh, cockpit만 허용 | 적절 |
| SELinux | Enforcing(강제) | 유지 권장. 서비스 등록 때 주의 필요 |
| SSH root 로그인 | 허용 | 키 접속 확인 후 **비밀번호 로그인은 끄기** 권장 |
| SSH 비밀번호 인증 | 허용 | 같은 이유로 끄기 권장 |
| NAS 연결 | 없음 | 추후 설정 |

## 6. 이 조사로 정해진 설치 방향

1. 전체 업데이트 후 재부팅 (커널이 바뀔 수 있으므로 드라이버 설치보다 먼저)
2. 서버 이름 정하기, SSH 비밀번호 로그인 끄기
3. 7.3TB 디스크 포맷 후 `/data`로 연결 → 모델·문서·색인 보관
4. cmake, EPEL 등 빌드 도구 설치
5. nouveau 차단 → NVIDIA 드라이버 설치 → `nvidia-smi`로 GPU 2장 확인
6. llama.cpp 빌드 → 한국어 모델(GGUF) 내려받아 첫 실행
7. NAS 연결, 서비스 자동 시작 등록

각 단계의 실제 절차는 `01_` 이후 문서에 적습니다.
