# 05. 대시보드에 AI 매니저 연동

- 작업 날짜: 2026-11-19
- 대상: 기술지원팀 업무 대시보드 `http://192.168.0.100:8080` (Synology NAS의 `dashboard` 공유 폴더, 노트북에서는 `Y:` 드라이브)
- 연결 상대: AI 서버 `http://192.168.0.193:8080` ([03. llama.cpp 설치와 모델 실행](03_llama_cpp_설치와_모델_실행.md)에서 띄운 llama-server)

직원들이 이미 쓰는 대시보드 화면에 "AI 매니저" 호출 버튼과 대화창을 붙였습니다.
대시보드 소스는 이 저장소에 없으므로(별도 관리), 여기에는 **무엇을 어디에 넣었는지**와 **동작 원리**, **문제 해결**만 기록합니다.

---

## 1. 화면에서 보이는 것

| 요소 | 동작 |
|---|---|
| "매니저" 동그란 버튼 | 오른쪽 위 글씨 크기 버튼(+ 100% −) 바로 아래. 스크롤해도 항상 보임. 좁은 화면(1300px 이하)에서는 글씨 크기 버튼처럼 오른쪽 아래로 이동 |
| 대화창 | 버튼을 누르면 화면 맨 위층(기존 팝업창보다 위)에 뜸. 제목줄에 "새 대화", "×(접기)" |
| 크기 조절 | 창의 오른쪽 아래 모서리를 끌어서. 바꾼 크기는 그 브라우저에 기억 |
| 위치 이동 | 제목줄을 잡고 끌어서 페이지 안 어디로든. 옮긴 위치도 그 브라우저에 기억(화면 밖으로는 못 나감) |
| 접기 | 대화창 바깥(사이트의 다른 부분)을 누르거나 Esc. 답을 만드는 중이어도 접힐 뿐 생성은 계속됨 |
| 대화 유지 | 탭 전환·새로 고침에도 남음. 브라우저 탭을 닫거나 로그아웃하면 사라짐. 계정별로 따로 보관 |
| 전송·중지 | Enter로 전송, Shift+Enter로 줄바꿈. 답을 만드는 동안 "전송" 버튼이 "중지"로 바뀜 |
| 게스트 | 버튼이 보이지 않고, 서버도 요청을 거부 |
| 휴대폰 폭(720px 이하) | 대화창이 화면 전체를 씀 (크기 조절 없음) |

## 2. 넣은 파일 (대시보드 쪽, `Y:` 드라이브)

| 파일 | 변경 | 역할 |
|---|---|---|
| `index.php` | 글씨 크기 버튼 아래에 버튼·대화창 HTML 추가, 맨 아래 `chat.js` 불러오기 한 줄 | 화면 뼈대. 게스트면 PHP에서 아예 출력하지 않음 |
| `style.css` | 끝에 `.ai-chat-*`, `.ai-msg*` 스타일 추가 | 기존 색상 변수만 써서 다크/화이트 테마 자동 적용 |
| `chat.js` | 새 파일 | 열기·접기, 제목줄 끌어 이동, 크기·위치 기억, 대화 보관(sessionStorage), 실시간 답변 표시, 중지, 가벼운 마크다운 표시 |
| `api/chat_stream.php` | 새 파일 | 로그인·CSRF 검사 → 게스트 거부 → AI 서버에 중계 → 답을 흘려보냄 |
| `config.php` | `LLM_API_URL`, `LLM_API_KEY` 두 줄 추가 | AI 서버 주소와 접근 열쇠. **키 값은 이 파일에만** |
| `config.example.php` | 같은 두 줄, 키는 빈 값 | 저장소용 본보기 |

`app.js`와 `auth.php`는 손대지 않았습니다. 되돌리려면 `index.php`에서 추가한 블록 두 곳을 지우고 새 파일 두 개를 삭제하면 됩니다.

## 3. 동작 원리 (한 번의 질문이 오가는 길)

```
직원 브라우저 ──(1) POST api/chat_stream.php {messages}──▶ NAS(PHP)
                                                           │ (2) 로그인·CSRF 확인, 게스트 거부, 세션 잠금 해제
                                                           │ (3) system 지침 + 최근 대화 20개 → AI 서버
                                                           ▼
                                             AI 서버 192.168.0.193:8080 /v1/chat/completions (API 키 필요)
                                                           │ (4) 답을 만드는 대로 "data: {...}" 줄로 보냄
직원 브라우저 ◀──(5) NAS가 그대로 흘려보냄(text/event-stream)──┘
         (6) chat.js가 줄마다 해석해 말풍선에 한 글자씩 덧붙임
```

- **API 키가 직원 PC로 나가지 않는 이유**: 브라우저는 NAS의 PHP만 호출하고, 키는 PHP가 AI 서버에 붙입니다.
- **세션 잠금 해제(`session_write_close`)**: 답이 길면 수십 초가 걸리는데, PHP 세션이 잠겨 있으면 같은 브라우저의 다른 요청(1분마다 도는 목록 갱신)이 모두 멈춥니다. 로그인 확인이 끝나자마자 세션을 닫아 둡니다.
- **nginx가 모아 두지 않게 하기**: `X-Accel-Buffering: no` 헤더와 PHP 출력 버퍼 해제. 실제로 2초 시점 131자, 4초 시점 271자로 글자가 실시간으로 쌓이는 것을 확인했습니다.
- **Qwen3의 생각 모드는 꺼 둠**(`enable_thinking: false`): 켜면 첫 글자까지 수십 초가 걸립니다.
- **대화 보관은 브라우저에만**: 서버(DB)에는 저장하지 않습니다. 필요해지면 MariaDB에 기록하는 기능을 추가합니다.

## 4. 확인한 것 (2026-11-19)

| 항목 | 결과 |
|---|---|
| 사이트 건강 | 로그인 화면 200, 비로그인 index.php 302, 중계 파일 비로그인 POST 401 |
| 게스트 | 버튼 없음, `chat.js` 오류 없음 |
| 관리자 계정 | 버튼 표시, 대화창 열림, 한국어 질문에 3초 안에 답 |
| 문맥 기억 | "그 중 첫 번째 명령의 -h 옵션은?"에 앞 답변의 `df -h`를 가리켜 설명 |
| 실시간 표시 | 2초 131자 → 4초 271자, 생성 중 "중지" 버튼 표시 |
| 새로 고침 | 대화 2개 유지, PC 폭에서 대화창이 오른쪽 위에 복원 |
| 바깥 클릭 | 접힘 확인 |
| 끌어 옮기기 | 제목줄을 끌어 (390, 280)으로 이동, 위치 저장 확인 |
| 코드 표시 | 답변 속 `df -h` 같은 명령이 코드 모양으로 표시 |
| 배치 | 1400px: AI 버튼이 글씨 크기 버튼 12px 아래 같은 세로줄. 659px: 오른쪽 아래 |

> **실수 기록:** 휴대폰 폭에서 전체 화면으로 열린 창 크기(628×852)가 "사용자가 조절한 크기"로 저장되어, PC 폭으로 돌아왔을 때 창이 거대하게 열렸습니다.
> 720px 이하에서는 크기를 저장하지 않도록 `chat.js`를 고쳤습니다.

## 5. 운영 메모

- **AI 서버가 꺼져 있으면** 대화창 아래에 "AI 서버에 연결할 수 없습니다. 서버(192.168.0.193)가 켜져 있는지 확인해주세요."가 뜹니다. 서버 전원과 `sudo systemctl status llama-server`를 확인합니다.
- **키를 바꿨을 때**: 서버의 `/data/llama-api.key`와 NAS의 `config.php` `LLM_API_KEY`를 같은 값으로 맞춥니다.
- **모델을 바꿨을 때**: 대시보드는 손댈 것 없음. 서버의 서비스 등록 파일(`/etc/systemd/system/llama-server.service`)만 고치고 재시작.
- **AI에게 주는 기본 지침(system 메시지)** 은 `api/chat_stream.php` 안의 `$systemPrompt`에 있습니다. 회사 소개, 말투, 답변 길이를 여기서 조정합니다.
- 다음 단계인 사내 문서 검색(RAG)은 이 PHP가 AI 서버에 보내기 전에 검색 결과를 지침에 끼워 넣는 방식으로 붙일 수 있습니다.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| 창이 이상한 곳에 있음 | 브라우저 개발자 도구 콘솔에서 `localStorage.removeItem('aiChatPos')` 후 새로 고침 (크기는 `aiChatSize`) |
| 버튼이 안 보임 | 게스트로 들어왔는지 확인. 직원 계정이면 `index.php`에 `aiChatFab` 블록이 있는지, `chat.js`가 200으로 받아지는지 확인 |
| "요청이 유효하지 않습니다" | CSRF 토큰 불일치. 페이지 새로 고침 |
| "AI 매니저는 로그인한 직원만" | 게스트 세션. 로그아웃 후 직원 계정으로 로그인 |
| "접근 열쇠가 맞지 않습니다" | `config.php`의 `LLM_API_KEY`가 서버의 `/data/llama-api.key`와 다름 |
| 답이 한 번에 뭉텅이로 뜸 | 중간 장비가 스트리밍을 모아 둔 것. 동작에는 지장 없음. nginx 리버스 프록시를 거친다면 `proxy_buffering off` 검토 |
| 답이 오다 끊김 | 서버 로그 `sudo journalctl -u llama-server -n 50` 확인. 대화가 너무 길면 "새 대화"로 시작 |
